# 安全规范

## 历史资产处置

工业项目一中的历史采集、LLM、Neo4j、训练和 Notebook 文件均为离线研究资产，不属于 Financial Risk Agent 的运行时依赖。新应用只能通过注册的 Repository 与 `integrations/legacy/` 适配器读取已登记的数据、图谱和模型包，不能导入、执行或包装历史脚本。

## 凭据事件处理

历史源码中曾出现过外部数据服务、LLM/OpenAI 兼容服务和 Neo4j 的明文凭据。本地源码已改为仅从环境变量读取，但这不能撤销已经暴露的值。

负责人必须在相应服务的管理后台完成以下动作：

1. 撤销或轮换所有曾出现在历史源码、Notebook、终端日志或版本历史中的凭据。
2. 删除不再使用的服务账户、令牌和数据库密码。
3. 将新凭据保存在受管理的密钥系统或本地未提交的 `.env` 文件中。
4. 记录轮换日期、负责人和受影响服务，但不得在本仓库记录凭据本身。

在负责人确认轮换完成前，所有历史凭据均按已泄露处理，任何历史模型或数据接入仅限本地离线验证。

## 数据、图谱与模型准入

- 每个可接入资产必须在 `data/manifests/legacy_assets.json` 中登记相对路径、内容哈希、来源、Schema 或特征版本、敏感级别和准入状态。
- 导入程序必须重新计算内容哈希；哈希不匹配时拒绝读取。
- 历史图谱中的无证据共现边必须标记为低证据强度，不能作为原文证据使用。
- 旧 checkpoint 只有在模型包清单补齐类别顺序、词表、特征构建器、阈值、数据版本和评估结果后才能注册为推理模型。
- 验证和测试数据不得参与训练词表、特征或阈值拟合。

## 运行时边界

- Agent 只调用白名单工具，不能调用 Shell、Notebook、动态模块、Neo4j 导入器或旧训练脚本。
- 日志、审计事件、任务状态、报告和资产清单不得保存 API Key、密码、令牌或完整凭据。
- 模型和数据读取是只读操作；任何转换必须输出新的、带哈希的产物引用。

## 受控修改边界

- 当前仅实现 `update_case_status` 与 `update_case_label` 两个中风险工具；二者均需要有效审批、完全匹配的 `proposal_hash`、固定参数模型和幂等键。
- 修改工具不进入只读 Tool Registry，也不能通过 LLM、页面参数、动态导入或任意 SQL 调用。
- 每次修改均保存修改前后摘要哈希、执行凭证和独立权威重读的校验结论；校验失败时只允许预定义补偿或进入人工处理。
- `HIGH` 和 `PROHIBITED` 操作没有执行入口。高风险提案必须审批，禁止操作在策略层无条件拒绝。
